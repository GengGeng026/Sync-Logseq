# 🚀 改進版 Logseq 同步系統

## 🆕 新功能特色

### 🧠 智能衝突處理
- **自動檢測衝突類型**：區分 Markdown 文件和其他文件
- **智能合併策略**：
  - 空內容自動選擇有內容的版本
  - 相似內容智能合併
  - 複雜衝突使用保守策略
- **Python 增強算法**：使用 Python 進行更精確的 Logseq 格式合併

### 💾 安全備份機制
- **自動備份**：每次處理衝突前自動創建備份文件
- **時間戳命名**：`filename.conflict_backup_YYYYMMDD_HHMMSS`
- **保留歷史**：不會覆蓋之前的備份

### 📊 詳細日誌記錄
- **衝突分析**：記錄衝突區塊數量和處理策略
- **處理結果**：清楚標示每個文件的處理方式
- **表情符號標記**：快速識別日誌類型
  - 🚀 開始同步
  - 🔧 檢測到衝突
  - ✅ 成功處理
  - ⚠️ 警告信息
  - ❌ 錯誤信息

## 🔄 衝突處理策略

### 1. Markdown 文件智能合併
```
策略優先級：
1. 空內容檢查 → 選擇有內容的版本
2. 衝突區塊分析 → ≤3個區塊使用智能合併
3. Python 算法 → Logseq 格式優化合併
4. Bash 備用方案 → 簡單內容合併
5. 保守策略 → 保留本地版本
```

### 2. 非 Markdown 文件
- **保守策略**：直接保留本地版本
- **安全優先**：避免破壞二進制文件

### 3. 複雜衝突處理
- **自動備份**：確保數據不丟失
- **分段處理**：逐個解決衝突區塊
- **回退機制**：失敗時使用保守策略

## 🛠️ 使用方法

### 切換到改進版
```bash
./switch_to_improved_sync.sh
```

### 測試衝突處理
```bash
./test_conflict_resolution.sh
```

### 手動啟動/停止
```bash
./start_logseq_sync.sh    # 啟動
./stop_logseq_sync.sh     # 停止
```

## 📋 日誌監控

### 查看實時日誌
```bash
tail -f sync_stdout.log
```

### 搜索衝突處理記錄
```bash
grep "🔧\|✅\|⚠️\|❌" sync_stdout.log
```

### 查看備份文件
```bash
ls -la *.conflict_backup_*
```

## 🔍 故障排除

### 如果智能合併失敗
1. 檢查 Python 是否可用：`python3 --version`
2. 查看詳細錯誤日誌：`tail -50 sync_stdout.log`
3. 手動恢復備份：`cp filename.conflict_backup_* filename`

### 如果需要回到原始腳本
```bash
cp logseq_sync.sh.backup logseq_sync.sh
./start_logseq_sync.sh
```

## 🎯 適用場景

### ✅ 完美處理
- 日誌條目添加/修改
- 簡單文本內容衝突
- 空文件 vs 有內容文件
- 少量衝突區塊（≤3個）

### ⚠️ 需要注意
- 大量複雜衝突（>3個區塊）
- 二進制文件衝突
- 網絡連接問題

### 🚫 不適用
- 需要人工判斷的語義衝突
- 重要的結構性變更衝突

## 📈 性能優化

- **Debounce 機制**：5秒延遲避免頻繁同步
- **日誌輪換**：自動管理日誌文件大小
- **進程清理**：自動清理 Git 鎖定文件
- **後台檢查**：每5分鐘檢查遠端更新
